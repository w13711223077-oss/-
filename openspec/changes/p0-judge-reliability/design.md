# Design

## Context

当前 P0 资产只有 3 道格式示范题与 `sample_annotation.json`（`p0_判定可靠性测试/README.md`），脚本 `p0_judge.py` / `p0_compare.py` 已能跑 baseline 与 broken 自检，但还没有 50—100 题的真实样本、标注复核、可复现报告与开关治理。`app/engine/judge.py` 的 `P0_已通过 = False`，`判()` 在 False 时返回「不判定」；**True 时会调用 `_判()`，而 `_判()` 目前是 `raise NotImplementedError`**（`judge.py:60-63`）。

**关键发现**：25·A-3 写「通过后只翻开关，让现成的三支反馈生效」，但代码里 `_判()` 尚未实现——**只翻开关会直接抛异常**。本设计把「开关可翻」定义为「P0 通过 + `_判()` 已实现并通过同一批用例回归」；`_判()` 的实现列入后续变更，不在本变更的规划范围内。

约束：零依赖 Python 标准库；不新增端点；不改 S1—S8 交互与 session 存储；样本只用公开/自编/教师提供题，不采集学生身份（CLAUDE.md §4/§7）。

## Goals / Non-Goals

**Goals:**

- 把 P0 从「有脚本」变成「有样本契约、标注契约、运行契约、指标口径、通过判据、开关治理、可复现」的实测工程。
- 让同一个样本集可重复执行并产出同一份四指标报告。
- 明确开关的开启条件与留痕方式；明确开关生效后的三态反馈与记录边界。

**Non-Goals:**

- 不实现 `_判()`（另开变更）；不翻 `P0_已通过`。
- 不做 S9/S10/S11、家长端、题库、RAG、任何第三方包。
- 不改 19 的端点形状、18 的数据契约、session 存储。
- 不做方向 B（暂停/继续）与方向 C（无判定教练）。

## Decisions

### D-01 真实样本与示范样本分离

新建 `p0_判定可靠性测试/samples/`（真实 50—100 题）与 `manifest.json`；保留 `sample_annotation.json` 作为「格式示范 + 管道自检」，不混入真实统计。理由：现有 3 题只够验证工具，不能算指标（README 已警告「3 道题错 1 条就是 33%」）。备选：直接扩展现有 `sample_annotation.json`——会让示范数据与统计样本纠缠，否决。

### D-02 标注文件与复核

真实样本每题的标注文件使用与 `sample_annotation.json` 相同的字段（`sentences` / `implicit` / `adjudication_cases`），新增 `reviewed_by` 与 `resolution`。单人标注，抽 ≥20% 由**教师**复核；不一致由第三人裁决并写 `resolution`。理由：P0 的核心风险是标注偏差，不是脚本。备选：双人全量标注——成本翻倍，50—100 题不划算。

### D-03 复用脚本，不新建框架

扩展现有 `p0_judge.py` / `p0_compare.py`，增加 `--samples` / `--manifest` / `--report-dir` 参数；保持 `--baseline` 与 `--model` 兼容。理由：21·ADR-001 零依赖、现有工具已能跑；新建 runner 只会多一套要维护的代码。备选：另写 `p0_runner.py`——否决。

### D-04 指标与分母固定

沿用 22·§二四个数字，分母写死：

| 指标 | 分子 | 分母 |
|---|---|---|
| 句子类型准确率 | 判对的句子数 | 全部句子数 |
| 三级准确率 | 判对级别的条件句数 | 全部条件句数 |
| 误判正例率 | 被判错的 `correct` 用例数 | 全部 `correct` 用例数 |
| 说不准率 | 不判定数 | 全部判定请求数 |

理由：分母不固定，数字就不可比。备选：按题平均——会掩盖长题偏差，否决。

### D-05 通过判据与开关治理

`P0_已通过` 只有在「误判正例率 = 0 + 两类准确率 ≥90% + 说不准率 ≤10%（估算）+ `_判()` 已实现并通过回归」时才可置 True。翻开关前必须有 `out/P0_摘要.json`（`passed=true` + 模型/提示词/样本版本），并在 `judge.py` 顶部注释与变更记录留痕。理由：`judge.py:28` 已要求「改这个值之前先看 P0_摘要.json」。备选：只靠口头确认——不可审计，否决。

### D-06 开关生效后的边界

开关只改变 `判()` 的返回值语义：S5/S6 从「不判定」变为三态；S8 的「未上线」提示消失；卡点仅在「不一致且 P0_已通过」时写入。`/answer` 仍是 `{verdict, session}`；session 存储、19 的端点、14 的可见性投影均不变。理由：15·§6.1 / 25·A-3；避免开关顺带改契约。

## Risks / Trade-offs

- **`_判()` 未实现，开关一翻就崩** → 在 FR-06 增加「`_判()` 已实现并通过回归」前置；把实现列入后续变更，不在本变更翻开关。
- **样本代表性不足** → 50—100 题按题型/结构分层；`manifest.json` 记录覆盖；不足 50 或超 100 直接拒绝。
- **标注偏差** → ≥20% 教师复核 + 第三人裁决；报告记录复核比例。
- **模型漂移** → 报告记录模型版本、提示词版本、样本版本、运行时间、命令；差异标「模型波动」。
- **样本版权/隐私** → 只用公开/自编/教师授权题；不写学生姓名/学校/班级/手机号；原题不进入产品库。
- **开关留痕不足** → `P0_摘要.json` + `judge.py` 注释 + 变更记录三处一致；缺一不可翻。

## Migration Plan

1. 建 `samples/` + `manifest.json`，先跑 `--baseline` 验证管道。
2. 收集/标注 50—100 题，完成 ≥20% 教师复核。
3. 扩展脚本，跑真实模型，产出 `P0_报告.txt` / `P0_摘要.json`。
4. 评估 Gate 0；不通过则保持 `P0_已通过=False`，转方向 C；通过则进入 `_判()` 实现变更（另开）。
5. `_判()` 实现并通过同一批用例回归后，才允许翻开关；翻开关后按 FR-09/10 回归 S5/S6/S8。
6. 回滚：把 `P0_已通过` 改回 False，恢复「不判定」；P0 报告与摘要保留，不删除证据。
