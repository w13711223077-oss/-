# Proposal

> **能力边界（先写清楚）**：P0 实测工程是「验证工具」，不是产品功能。它不进入产品运行链路，不新增端点，不改 S1—S8 交互，不动 session 存储。唯一会改变产品行为的是：**开关被翻过之后，S5/S6 的三态反馈生效**——这部分单列为「开关生效后的行为规格」（FR-09）。

## Why

Gate 0 判定可靠性尚未实测：`app/engine/judge.py` 的 `P0_已通过 = False`，S5/S6/S7 的「一致 / 不一致」两支从未在真实题目上验证过（25·§三 A、22·§二）。在拿到「误判正例率 = 0」之前，任何依赖判定的功能都建立在未验证的假设上；现在需要把 P0 从「有脚本」变成「有样本契约、有标注契约、有可复现指标、有开关治理」的实测工程。

## What Changes

- 把 P0 的**样本契约**、**标注契约**、**运行契约**、**指标口径**、**通过判据**、**开关治理**、**可复现要求**写成可验收的规格。
- 明确 P0 资产的位置、命名、输入输出文件与字段，使同一个样本集可被重复执行并得到同一份数字。
- 明确 `P0_已通过` 的翻开关条件：误判正例率 = 0；不通过不得改开关。
- 明确开关翻过之后 S5/S6 的行为变化（三态反馈、S8 提示消失、卡点开始写入），**不改** 19 的端点形状、18 的数据契约与 session 存储。
- **不做**：S9/S10/S11、家长端、题库、RAG、任何第三方包、方向 B（暂停/继续）、方向 C（无判定教练）。

## Capabilities

### New Capabilities

- `judge-reliability`: P0 判定可靠性实测工程——样本/标注/运行/指标/门禁/开关治理/可复现，以及开关生效后的三态反馈边界。

### Modified Capabilities

（无。现有 `openspec/specs/` 为空；本变更不改任何既有能力规格。）

## Impact

- **测试资产**：`流程步骤/3.验证与商业/p0_判定可靠性测试/` 新增真实题目样本、标注与报告；不改产品代码。
- **文档**：22·§二/§六、25·§三 A 被引用；`19`/`18`/`session` 契约**不变**。
- **代码**：只有 `app/engine/judge.py` 的 `P0_已通过` 开关可能从 `False` 变为 `True`；`_判()` 的实现属于后续变更，不在本变更范围内。
- **依赖**：无新增；仍为 Python 标准库。
- **合规**：样本只用公开/自编题；不采集学生姓名/学校/班级/手机号（24·§二）。
