# Proposal

> **能力边界（先写清楚）**：本变更是「架构审查 + 文档契约对齐 + 上线门禁与后续变更分派」，不是认证实现。它不新增端点、不改代码、不改 session 存储，也不实现 token/过期/删除/限速。审查发现的 P0 实施项（DM-02、DM-03、AU-01、AU-02、AU-03）已分派到后续变更并设阻断门；**归档本变更不等于系统可上线或可做真实家庭实测**。

## Why

18（数据模型）与认证体系（当前未建）从未与 `app/` 代码逐条核对。25·§2.2 又暴露了 18/19 多处文档与实现漂移（D1—D4、D7）：照着 19 的旧契约实现会把 `prep` 发给学生，直接踩「不给答案」红线。

在 Gate 1（3—5 个真实家庭）之前，必须先回答三个问题：数据模型能否支撑 Gate 0—3、认证能否在不推翻 ADR-001/003 的前提下补齐、本期 P0 实测工程能否在不修这些问题的情况下开工。没有这份审查基线，后续每个变更都会在未验证的假设上叠代码。

## What Changes

- 新增 `26-架构审查-数据模型与认证.md`：核实 K1—K5，产出数据模型 8 条 findings（DM-01—DM-08）、认证 5 条 findings（AU-01—AU-05）、J1—J3 判定与 Q1—Q5 拍板结论。
- 修正 18·§2.9/§四：`session_events.jsonl` 标为「已定义未实现」，存储表同步（25·D7）。
- 修正 19·§一/§3.3/§3.4/§3.6/§六：`/confirm` 不再返回 `prep`；`/answer` 改为 `{verdict, session}`；`GET` 不含 `prep`；`E_DEDUP` 标为 v2 预留，同目标重复返回 `E_LIMIT`（25·D1—D4）。
- 修正 14·§四：删除「只能被创建它的客户端读写」的无支撑承诺，改为「持有 `session_id` 即可读写」（26·K4/AU-02）。
- 在 26·§七 增加归档前复核补记：DM-07 已由 `90e24e0` 修复；测试数 63 与文档 60 的差异留待后续文档修正（属 12·D5，不在本变更）。
- 记录后续变更与阻断门：`session-auth-hardening`、`session-lifecycle`、`s9-s12-data-model`。

**不做**：不实现认证、不做 schema 迁移、不加 `expires_at`/删除入口、不改 S1—S8、不改端点/存储、不扩 S9—S12 实体、不翻 `P0_已通过`。

## Capabilities

### New Capabilities

- `data-model`：会话文档为唯一真源、审计事件状态真实、版本化/保留期门禁、审查缺口可追溯。
- `session-auth`：v1 无认证的真实边界、隔离表述不得超出实现、上线前最小认证门禁、受控实测条件、认证缺口分派。

### Modified Capabilities

（无。`openspec/specs/` 原为空；本变更只新增能力规格，不改既有能力。）

## Impact

- **文档**：14、18、19、26；**代码 0 改动**；**测试 0 改动**（后端 63、P0 37 全部通过）。
- **契约**：19 的对外响应描述与现有代码对齐，不改变实际端点行为。
- **合规**：24 的未成年人数据条款；公开分发前由 `session-auth-hardening` 阻断。
- **依赖**：无新增；仍为零依赖 Python 标准库。
- **关联变更**：`p0-judge-reliability` 保持活动状态，不在本变更范围内。
