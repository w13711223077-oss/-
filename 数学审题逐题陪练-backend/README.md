# 数学审题逐题陪练 · 后端骨架

> **这是一个骨架，不是产品。** 它把「v1 该怎么落地」这件事变成可以跑的东西。
> 最后更新：2026-10-01

---

## 一、它解决什么

`11-产品设计.md` §8.2 那个红框里写着：

> **F14 建错题库，指向「要有存储」——而 v1 是 HTML、无后端。这是硬冲突。**

三条出路（加极薄存储 / 先不做 F14 / 用导出文件代替），**已选 A**。
这个目录就是 A 的落地。

顺带把 §8.1 那张表里的另外两行也一起了了：

| §8.1 的限制 | 现在的状态 |
|---|---|
| 无后端、无数据库 | 有了极薄存储层（追加式 JSONL） |
| API 密钥暴露在网页源码里 | 有了转发层——key 只在服务端环境变量里，永远不进响应 |
| 本地文件直调接口被跨域拦 | CORS 头已带；也可以 `--static` 把网页同源发出去 |

## 二、怎么跑

零依赖，**不用装任何东西**，Python 3.7+。

```bash
cd 数学审题逐题陪练-backend
python run.py
```

想真调模型，先设 key：

```bat
set DEEPSEEK_API_KEY=sk-xxxx          :: Windows cmd
$env:DEEPSEEK_API_KEY="sk-xxxx"       :: PowerShell
export DEEPSEEK_API_KEY=sk-xxxx       :: macOS / Linux
```

不想花钱、只想验证管道通不通：

```bat
set PEILIAN_STUB=1
```

> **桩模式照 `p0_judge.py --baseline` 的道理**：先证明整条链是通的，再去调真的模型。
> 一个永远不会失败的检查，等于没有检查。

跑测试：

```bash
python -m unittest discover -s tests -v
```

## 三、端点

分两组，加两个元信息端点。

### 端点组① —— 转发模型调用（藏 key）

| 方法 | 路径 | 干什么 |
|---|---|---|
| POST | `/api/v1/model/read` | **F1 拍照识题**。收图片（或文本），返回抄写出来的题目 |
| POST | `/api/v1/model/forward` | 通用转发。给 F2 备课 / F3 判定 / F10 批改 之后复用 |

`model/read` 的口径和 `5.创建项目骨架/v1/index.html` 里那段读图提示词**保持一致**：
只让它「抄题」，不让它「解题」——**抄写是转录，解题越界了**（§5·9.4）。
印刷不清的地方照抄、不要猜：**猜出来的题目，比读不出来更危险。**

顺带一个设计上的好处：`mode: "text"` 走的是 §4.1·F13 的兜底输入（粘贴文本），
**不经模型**——白捡一个 F13。

### 端点组② —— 存记录

| 方法 | 路径 | 干什么 |
|---|---|---|
| POST | `/api/v1/exercises` | **S12 落库**。写一次练习，同时写进错题库 ＋ 卡点记录库 |
| GET | `/api/v1/exercises` | 读练习记录（`?练习ID=` / `?limit=`） |
| GET | `/api/v1/pending` | **未清账目** —— 第九节 #2「重练的入口」 |
| POST | `/api/v1/wrong-items/done` | 把一道错题标成「重做过了」 |

### 元信息

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/v1/health` | 状态、桩模式开没开、key 配没配 |
| GET | `/api/v1/schema` | **把数据契约摊平返回**——前端照着它对字段 |

## 四、几个想清楚了才敢写的地方

### 「账」和「画像」不是一回事

`/api/v1/pending` 里有两样东西，但它们**性质不同**：

| | 是什么 | 会不会清零 |
|---|---|---|
| **未清错题** | **账**。重做一遍就划掉 | 会 |
| **未清卡点** | **画像**，不是待办 | **不会，也不该会** |

§6·决策 4 说卡点记录唯一的价值是「**维度长期稳定**」——
它是一张对照表，不是一个待办清单。**拿它算「还有几件事没做」是理解错了它。**
所以 `有账` 这个字段只看错题。

### F3 判定引擎**现在是故意的「不判」**

`app/engine/judge.py` 的默认输出是三种结果里的第三种：**不判定**。

这不是「还没写」，这是 §8.3 要求的：

> 这一条不通过，F3 的判定就不能上线——那时产品形态要改，
> 而不是硬着头皮写代码。

「这一条」= P0 判定可靠性测试。**在 P0 拿出「误判正例率 = 0」之前，
这个后端没有资格判对错。** 契约（一致 / 不一致 / 不判定）已经定死了，P0 通过后只换实现，前端不用改。

### 存储是「只追加」的

三个股全部 append-only：`exercises.jsonl`、`beads.jsonl`、`wrong_items.jsonl`。
标记「重做过了」不是去改原记录，而是**再追加一条事件**，读的时候合并。

理由：§6·决策 4 说这些记录的价值在「维度长期稳定」——
不改写，等于每一次写入都留痕。顺带省掉一个数据库。

## 五、目录

```
数学审题逐题陪练-backend/
├── run.py                    启动入口
├── app/
│   ├── main.py               HTTP 服务与路由（零框架）
│   ├── api/
│   │   ├── forward.py        端点组①：转发（藏 key）
│   │   └── records.py        端点组②：存记录 / 未清账目
│   ├── domain/schema.py      数据契约 —— 全后端唯一「拟字段」的地方
│   ├── engine/judge.py       F3 判定引擎（现在是「不判定」）
│   └── store/jsonl_store.py  追加式 JSONL 存储
├── tests/                    29 个测试
└── data/                     运行时生成，已 gitignore
```

### `domain/schema.py` 是唯一会「编」的地方

`11-产品设计.md` 给的是**名字**，不是**字段名和类型**。所以那份文件里：

- 凡是**值**（`"背景"` / `"直接"` / `"隐含条件未说出"` …）—— 照文档原话，**一个字不改**
- 凡是**字段名和类型** —— 是本骨架的推断，改它不需要改产品设计

每条后面跟 `[源: §…]` 指出它从文档哪一句来；文档没写的标 `[推断]`。

| **前端没动** | 这一轮的目标是「后端先独立跑通」。`v1/index.html` 还是直连 DeepSeek 的 |
| **F3 真的判定** | 等 P0（见上） |

| **鉴权** | v1 只在受控范围内用（§8.1）。**上线前必须补** |
| **并发写** | 现在是进程内一把锁。单机自用够；多进程共用要换成带锁的存储 |
