# 21. 技术选型与工具链 — 数学审题逐题陪练

> 上游：17、19、20。下游：22、23。
> 样板 37 号文用 ADR 记录每条选型的理由与放弃项；本文按同样方法，但技术栈**刻意比样板薄一个数量级**。
> 三条原则：够用就好；社区验证优先；每个选择记 ADR。

## 一、总览

| 层 | v1 选择 | 放弃 |
|---|---|---|
| 后端 | Python 3.10+ 标准库（`http.server`） | FastAPI/Flask/Django |
| 前端 | 单页 HTML + 原生 JS | React/Vite/Tailwind |

## 二、ADR

### ADR-001 后端：Python 标准库，不引框架

**决定**：`http.server` + 手写路由；零第三方依赖。
**理由**：项目现有 `setup_env.py`、P0 工具都是零依赖 Python；v1 只有 11 个端点；用户机器上不用装任何东西。
**放弃**：FastAPI（自动 OpenAPI/SSE/Pydantic 校验，但引入几十个包；v1 用不上）。
**代价**：手写路由/校验/错误处理；并发是进程内线程；上线前要补鉴权与限流。
**升级路径**：端点数/并发上来后，按 19 的契约换 FastAPI，前端不改。

### ADR-002 前端：单页 HTML + 原生 JS

**决定**：一个 `index.html`，内联 CSS/JS，零构建。
**理由**：v1 只有一个流程 8 个状态；无路由、无复杂状态管理；改完刷新即生效。
**放弃**：React/Vite（组件化收益 < 构建链成本；样板教师端才需要）。
**代价**：手写 DOM 渲染；复杂交互（流式、富文本）以后要重构。
**升级路径**：如果 v2 加 S9—S12 + 家长/教师端，再评估 Vite/React 或继续多页原生。

### ADR-003 存储：JSON/JSONL，不上数据库

**决定**：会话一个 JSON 文档；事件/记录 append-only JSONL。
**理由**：11·§8.2 选 A 的极薄存储；单机、单用户；记录结构先定死比换数据库重要。
**放弃**：SQLite（零运维但仍有 schema/migration 成本；v1 数据量小）。
**代价**：无事务、无索引、并发写靠进程内锁；多进程要换存储。
**升级路径**：数据量/并发上来换 SQLite；18 的实体/字段可直接映射表。

### ADR-004 模型：DeepSeek 原生读图，不搭 OCR 层

**决定**：图片直接进 `deepseek-flash`，只让它「抄题」；文本走 F13 兜底。
**理由**：01·E4/05·1.4：原生多模态让「一个人 + 一台电脑」可以起步；少一个组件、少一处失败点。
**放弃**：PP-OCR/Baidu OCR/MinerU（样板 23 的三引擎；对单题手机拍照是过度设计）。
**代价**：模型「能看见 ≠ 看得准」；必须保留 S2 确认与可改；读错一个负号后面全错。
**兜底**：S2 人工确认 + F13 粘贴文本；读题失败可重拍。

### ADR-005 语音：浏览器 Web Speech API

**决定**：`speechSynthesis`，`zh-CN`；只读教练话术，不读题目正文。
**理由**：零外部服务、零成本、零延迟；第一版先把「教练开口」跑出来。
**放弃**：云 TTS（延迟/成本/供应商）；流式分段 TTS（v2 再做）。
**代价**：音色/稳定性依赖浏览器；移动端可能限制自动播放（需用户手势）。

### ADR-006 流程：确定性状态机，不用自由 Agent

**决定**：`flow.py` 管 12 个状态与 8 条守卫；LLM 只在备课/判定/追问内部工作。
**理由**：单流程、强顺序、短会话；可复现、可测试；避免 LLM 跳步/提前给结论。
**放弃**：LangGraph ReAct（样板 29 适合多工具多意图；我们是单流程）。
**代价**：灵活性低；开放式问答以后要另加。
**升级路径**：v2 若要加「自由问教练」，再加一个受限的 Q&A 工具，不替换主流程。

### ADR-007 v1 无账号/无鉴权

**决定**：`session_id` 随机隔离；不采集身份信息。
**理由**：06·二 教师试用无登录；01·L1 不采集姓名/学校/班级/手机号。
**放弃**：JWT/账号体系（v1 是受控范围验证版）。
**代价**：**上线前必须补鉴权**；否则任何人拿到 session_id 可读会话。
**升级路径**：账号 + 监护人同意 + 删除权（24）。

### ADR-008 不给答案的工程保障

**决定**：数据模型里不存在 `answer/solution`；模型输出剥离答案字段；批改只给数量级。
**理由**：11·§四决策 8、24：这是产品身份与合规身份，不是文案。
**放弃**：把答案存服务端再“前端不展示”（仍可能泄露/被 prompt 套出）。
**代价**：批改/变式审核需要独立的标准答案通道（只给内部审核器，不进学生响应）。

## 三、开发工具链

对齐样板 37·§八 的五层，但按单人项目裁剪：

| 层 | 工具 | 在本项目里的角色 |
|---|---|---|
| 思考层 | `/office-hours` `/plan-ceo-review` `/plan-eng-review` | 需求/方案讨论 |
| 规格层 | OpenSpec `/opsx:propose → apply → archive` | 变更提案 → 实现 → 归档 |
| 实现层 | TDD：先红后绿 | 单元/流程/HTTP 测试 |
| 质量层 | `unittest` + Gate 0—3 + P0 工具 | 确定性测试 + 红线实测 |
| 流程层 | `/review` `/qa` `/ship` `/retro` | 代码审查/验收/发布/复盘 |
| 骨架层 | Git + no-mistakes | 分支/提交/推送门禁 |

> 工具本体用 `setup_env.py` 装；沙箱每次会话重置，用户机器上持久。

## 四、成本与性能

| 项 | v1 估算 |
|---|---|
| 模型成本 | 一次首体验约 1 次读图 + 1 次备课 + 3—6 次判定；按 deepseek-flash 定价，角分量级 |
| 延迟 | 读图 2—5s；备课 3—10s；判定 <2s；首体验主要耗时在学生思考 |
| 并发 | 单机 `ThreadingHTTPServer`；v1 3—5 个家庭，够用 |
| 存储 | 一次会话 <10KB；JSONL 追加；无清理策略（v1 手动） |

## 五、升级触发条件

| 触发 | 换什么 |
|---|---|
| 同时在线 >10 / 需要多进程 | SQLite/Postgres + 进程外锁 |
| 需要账号/家长端/教师端 | 鉴权 + 角色权限（14） |
| 需要流式对话 | SSE + 前端事件渲染 |
| 需要 S9—S12 批改 | Gate 2 测试集 + 批改引擎 |
| 需要多模型 fallback | Provider 路由（样板 37 的三级 fallback） |
| 需要公网 | HTTPS、CORS 收紧、密钥管理、备案 |
