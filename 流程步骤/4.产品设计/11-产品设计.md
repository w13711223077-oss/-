# 产品设计 — 数学审题逐题陪练系统

> 市场：中国 K12 AI 辅助学习工具（C 端 · 学生 / 家长付费）
> 学段：初中七年级 · 应用题
> 日期：2026 年 9 月

> **这份文档要回答四件事**：产品**做什么**、**解决什么问题**、**用户怎么使用**、**功能怎么协作**。
>
> **写法约定**：本文的每一条设计决定，都要能回溯到 `01`—`10` 的某一条分析。
> **凡是没有来源的，我会标「待议」**——不把拍脑袋写成设计。

## 一、从分析到产品：约束是怎么收敛下来的

前十份文档给的不是「想法」，是**约束**。产品设计的任务，是把这些约束变成一串具体决定。

| 来源 | 给出的关键约束 | 落到产品上的决定 |
|---|---|---|
| `01`·P1 | 「学生独立使用 ＋ 拍照 ＋ AI」落在「拍照搜题」的监管与舆论阴影里 | **不给答案**，且要成为**形态特征**而不是文案 |
| `01`·T1 / `01`·E4 | `deepseek-flash` 原生读图（2026-09-10 起） | 拍照**直接进模型**，不搭 OCR 层 |
| `01`·L1 | 七年级 12—13 岁，整体落在「不满十四周岁」 | 不采集姓名 / 学校 / 班级 / 手机号 |
| `02`·ST-1 | 「不给答案」要**可被第三方验证** | 产品里**不存在「答案」入口** |
| `02`·P0 | 判定可靠性是整条链的地基 | **不确定时不判定**，转为提问 |
| `03`·5.1 | 用户生命周期天然只有一年 | **卡点记录从第一天开始**，结构一旦定稿不再改 |
| `04`·三 | 「审题训练」在 50 维矩阵中无任何竞品 | 只做审题，不碰解题 / 题库 / 排名 |
| `05`·8.3 | **误判正例率必须为 0**（红线） | 判定引擎必须有「不判」这个输出 |
| `06`·二 | 家长端只有 1 个触点、约 30 秒 | **v1 不做家长端**（v1 是验证版；家长端需要专门的推送与展示层） |
| `06`·二 | 陈老师产品内行为 = 0 次 | **不做教师端界面** |
| `07`·D.2 | 「43 分钟」与「≤15 分钟」互相矛盾，且两边都无依据 | **拆成两段**：首体验（S1–S8）≤15 分钟；完整闭环（S1–S12）只记录、不设目标 |
| `06`·一 | 43 分钟走查拆开：审题 17 / 写 12 / 批改 4 / 变式 9 / 收束 1 | 15 分钟只约束**产品陪练的那一段**，不约束学生写作业 |
| `08`·三 | 首次体验的转折点在 S7（自己说出隐含条件），在写解答之前 | **首体验到 S8 收束**；S9–S12 是「可选的后续」 |
| `09`·四 | 同一句话，对家长是差异化、对学生可能是「这工具没用」 | 对学生**不说「不给答案」**，说「它觉得你能想出来」 |
| `10`·三 | 一位教师一年只带来约 5—8 个付费家庭 | **v1 必须极简**，第一要务是能验证，不是能做全 |

**一句话**：这份产品设计的每一个选择，都是在回答「**怎么在不给答案的前提下，把审题这件事变成可训练的**」。

## 二、产品要解决什么问题

### 2.1 核心问题

> **学生做作业卡住时，没有人能陪他把题读完。**

这句话里的每一个字都有来源（`05`·1.2、`06`·P1）：

- **「卡住」**——不是不会算，是不知道从哪下手
- **「没有人」**——家长讲不清（`01`·S4）、老师问不到（`06`·P1）、搜题直接给答案（`04`·二）
- **「陪他把题读完」**——不是替他做，是陪他读懂

### 2.2 三个具体问题

| # | 问题 | 具体表现 | 来源 |
|---|---|---|---|
| **一** | **「认真读题」是一个没有动作的指令** | 这句话从小学听到初中，但没人告诉他具体该圈什么、划什么、分几步 | `06`·P1·痛点 2；`手册` |
| **二** | **卡住时无处可去** | 喊家长→讲不清→吵架；问老师→不好意思；搜题→抄答案 | `06`·P1·What Before；`07`·一·Alternatives |
| **三** | **他不知道自己错在哪一类** | 以为是粗心，其实没看见隐含条件 | `06`·P1·痛点 1 |

**问题的形状决定了产品的形状**：因为问题一是「没有动作」，所以产品要有**具体动作**；因为问题二是「无处可去」，所以产品要**随时可用、且不替代他思考**；因为问题三是「说不清」，所以产品要**把错误落成具体环节**。

### 2.3 产品**不**解决什么

**这一节和上一节同样重要**——它划的是边界，不是谦虚。

| 不解决 | 为什么 |
|---|---|
| **不会算** | 那是解题能力。产品只处理「读懂」，学生卡在计算上时，本产品帮不上 |
| **练得不够** | 那是题库的职责。审题训练**不替代刷题**，它解决刷题替代不了的那个问题 |
| **提分** | 分数是能力的结果，不是产品的承诺（`05`·第三节：愿景里故意不写提分） |
| **家长不知道孩子学得怎么样** | 这是真实的痛点，但 **v1 不做家长端**（`06`·二：她一周只有一个 30 秒触点；v1 是验证版，不做推送与展示层） |
| **老师没时间逐个盯** | 这是产品想间接缓解的，但**不通过给老师做工具**来实现（`06`·二：她不打开产品） |

## 三、用户怎么使用：一次练习的完整过程

> **这一节是全文的核心。** 它把前面所有约束摊成一条学生真实走过的路。

### 3.1 先说三件「形态」上的事

**第一，这不是一个「打开 App 开始刷题」的产品。**

`06`·二 记过一个数字：学生使用频率是**每周 2—3 次**，而且**不是每天**——他是「**卡住的时候才打开**」。
所以产品没有首页、没有课程、没有列表、没有进度。**打开就是拍题。**

**第二，首体验设 15 分钟，完整闭环不设总时长。**

`07`·D.2 里我们自己戳破过：「≤15 分钟」是拍脑袋定的；`06` 的 43 分钟走查也不是实测。
**但这两个数字量的不是同一段路**——把 43 分钟拆开：

| 段 | 走查时长 | 是什么 |
|---|---|---|
| **S1–S8** | **17 分钟** | 拍照 → 确认 → 开场 → 逐句标注 → 隐含条件 → 收束 |
| **S9** | **12 分钟** | 学生在纸上写解答——**这是作业，不是产品时间** |
| **S10–S12** | **14 分钟** | 拍照回传、批改、变式题、收束 |

所以现在的口径是两条：

| 对象 | 约束 | 怎么管 |
|---|---|---|
| **首体验**（S1–S8） | **目标 ≤15 分钟，红线 20 分钟** | 产品陪练时间；决定「第一次还会不会来」 |
| **完整闭环**（S1–S12） | **不设总时长**，照常记录 | 作为观测指标，不作为设计目标 |

**为什么首体验到 S8 为止**：`08` 写得很清楚——首次体验的转折点是孩子「拍照、听语音、点句子、自己打出『总人数不变』」，那是 S7；**转化发生在写解答之前**。S8 的「这道题你已经读明白了」本身就是一个完整收束。S9 的 12 分钟是他本来就要花的作业时间，不是产品增加的负担；把它算进 15 分钟，等于用「学生写作业慢」来判产品的死刑。

单步约束继续保留，两条一起用：

| 约束 | 值 | 管什么 |
|---|---|---|
| **思考下限** | **15 秒** | 学生没动静时，系统**至少等 15 秒**再开口——不催 |
| **单步上限** | **40 秒** | 一步超过 40 秒还没过，**不是学生慢，是这一步设计得不对** |
| **机器响应** | **尽快，不设数字** | 系统自己的延迟是工程问题，不写进产品约束 |

**为什么是 40 秒——它不是一个孤立的数字，它正好是一次降梯的完整周期**：

```
学生不动 ──15 秒──→ 给一条提示（约 5 秒）──15 秒──→ 仍不动 → 记「卡住」，继续
        └──────────────── 约 35 秒 ────────────────┘   上限 40 秒留 5 秒缓冲
```

**这条上限等于从时间上强制了「降梯只降一次」**——不是靠规则约束，是靠时间装不下第二次。
两条约束互相咬合，比单独写一条「不要反复追问」更难被违反。

总时长照常记录——但记两个数：**首体验时长（S1–S8）** 和 **完整闭环时长（S1–S12）**。

> **沿革（2026-10-28）**：本节原来写「一次练习不设总时长」，把 43 与 15 的冲突整个绕开了。
> 现在拆成两段：首体验 ≤15（S1–S8），完整闭环只记录。**改的是「15 分钟管哪一段」，不是 15 这个数。**

**第三，产品的动作是「一格一格往前走」。**

学生任何时刻都知道两件事：**现在在做哪一步**、**下一步是什么**。没有浮动的进度条，没有「再答几题」。

### 3.2 全流程总览

```
S0 触发（做作业卡住）
      ↓
S1 拍照                      ← 学生的动作只有这一个
      ↓
S2 确认题目                  ← 识别结果摆出来，可改
      ↓
S3 备课                      ← 学生不可见。系统自己把题解剖一遍
      ↓
S4 开场                      ← 「不着急做，我们先把题读一遍」
      ↓
S5 逐句标注（4—6 句）        ← 判定型·点选
      ↓
S6 条件定级（2—3 条）        ← 判定型·点选
      ↓
S7 隐含条件追问              ← 开放型·打字，可以说不出
      ↓
S8 收束                      ← 「这道题你已经读明白了」｜首体验到此（≤15 分钟）
      ↓
S9 学生自己写解答 → 拍照      ← 学生写，系统不介入｜以下为可选的后续，不计入首体验
      ↓
S10 批改                     ← 判对错 + 内部定位（对外只说数量级）→ 矫正
      ↓
S11 变式题                   ← 条件触发；首体验不触发
      ↓
S12 生成错题库 + 卡点记录库   ← 之后可以重练这些题、这些卡点
```

**S1—S8 是首体验弧线（≤15 分钟）；S5—S7 是审题主体，S9—S10 是「不给答案」的落点，S11 是验收。S9 之后是可选的后续，不计入首体验。**

---

### S0｜触发：他为什么打开

| | |
|---|---|
| **学生** | 做作业卡在最后一道应用题上，读了两遍不知道从哪下手 |
| **系统** | 什么都不做 |
| **关键** | **这个时刻是产品的起点，而不是「登录 / 选课 / 选年级」** |
| **依据** | `06`·一·小然一个做作业的晚上（19:40） |

**设计含义**：产品**不应该有任何前置步骤**——没有注册、没有登录、没有选年级。
`08`·2.3 已确认：**C 端的决策周期是数分钟，本产品没有「销售」，只有「第一次体验」。**
**任何一道前置门槛，都是在最有价值的那 30 秒里加一道墙。**

---

### S1｜拍照

| | |
|---|---|
| **学生** | 拍一张题目 |
| **系统** | 接收照片 |
| **单步上限** | 40 秒（含他摆正、重拍） |
| **失败走向** | 拍糊 → 提示重拍；识别不出 → **允许直接粘贴文本**（兜底通道） |
| **依据** | `06`·P1·产品适配：① 拍照识题 ✅ 直接命中（他就是拍题，不是打字） |

**为什么拍照而不是打字**：`06`·P1 已经确认他**打字慢**（一句话要几十秒到一分多钟）。
**让他把整道题敲进电脑，等于在第一分钟就劝退。**

**为什么必须保留「粘贴文本」的兜底**：`02`·W6 记过——识别会出错，而且**它是唯一一个「出错就全错」的环节**（读错一个负号，后面全错）。

---

### S2｜确认题目

| | |
|---|---|
| **学生** | 看一眼系统读出来的题目，有错就改 |
| **系统** | **把识别结果显式摆出来** |
| **单步上限** | 40 秒 |
| **依据** | `01`·T1：模型「能看见 ≠ 看得准」；`05`·8.3 |

**这一步有双重价值**，缺一不可：

1. **它是防错闸门**——`02`·W2 已经说明：**备课错一次，后面全错，学生会照着错误的标准改自己**
2. **它本身就是审题训练的第一环**——核对「题目到底在说什么」，正是审题要练的动作

**所以这一步不能做成「后台自动识别 → 直接进入」。** 让它可见、可改，不是妥协。

---

### S3｜备课（学生不可见）

| | |
|---|---|
| **学生** | 在等（界面要给「我在准备」的信号，不是死寂） |
| **系统** | **把题目完整解剖一遍** |
| **依据** | `02`·W2、`02`·ST-2、`05`·8.3 红线 |

**备课要产出什么**（这是功能清单 F2 的内容，这里先说它产出什么）：

| 产出 | 用途 |
|---|---|
| 分句结果 | S5 逐句出示 |
| 每句的类型标注 | S5 的判定基准 |
| 每条条件句的级别 | S6 的判定基准 |
| **隐含条件集合**（注意是**集合**，不是单点） | S7 的判定基准 |
| 每条判断的依据 | 判定时要说给学生听 |

**为什么备课必须前置、且必须独立完成**：
`02`·W2 写过——**边陪边判会前后不一致**。而且**判定错一次，学生就会照着一个错误的标准改自己**。
这是这条链上唯一一处**「宁可慢，也不能错」**的地方。

**一个重要的兜底**：备课时如果系统对某一项**不确定**，它必须**把这一项标记为「不判定」**——
S5/S6/S7 走到那一项时，**不判对错，只提问**。这是 `02`·ST-2 那条「不确定时不判定」的落地方式。

---

### S4｜开场

| | |
|---|---|
| **学生** | 听 |
| **系统** | 第一句话：**「准备好了吗？我们先把这道题读一遍，不着急做。」** |
| **依据** | `05`·7.1；`06`·一（19:45） |

**这一句话要同时完成三件事**：

1. **定调**——「不着急做」，把学生从「赶作业」的心态切出来
2. **划线**——全场**不出现解法**，学生听完就知道这不是一个给答案的工具
3. **拿到许可**——他如果不愿意读题、只想抄答案，现在就会退出。**早退出比走到一半退出便宜**

**这也是「品类澄清」的一次机会**：`02`·ST-1 要求「不给答案」可被第三方验证——
**开场第一句就是最直接的验证点。**

---

### S5｜逐句标注（判定型）

| | |
|---|---|
| **学生** | 系统出示一句，他点选：**背景 / 条件 / 问题 / 指令** |
| **系统** | 出示一句 → 等 → 判 → 反馈 |
| **步数** | **4—6 句**（由 S3 的分句结果决定） |
| **单步约束** | 15 秒思考下限 / 40 秒上限 |
| **依据** | `04`·三 第 16 项（本产品独有的能力）；`手册`·四类句子 |

**系统的三种反应**（这是判定的核心，`02`·ST-2 的三条硬规则）：

| 情况 | 系统怎么反应 |
|---|---|
| **与备课一致** | 确认——**夸具体动作**（「对了。像这种不讲数量、只交代情境的句子，就是背景句」），**不夸聪明** |
| **与备课不一致，且备课是确定的** | **不说「你错了」**——改为指向线索：「**它在给数字，还是在问你什么？**」 |
| **备课标了「不判定」** | **不判对错**——改问：「**你为什么这么想？**」 |

**三条约束**：
- 一次只推进一句（不是一次问完整道题）
- 夸的是**动作**不是人（`手册`：夸「你今天圈得很全」而不是「你真聪明」）
- 判错时必须**给依据**（「这句话没有给出数量关系，所以它不是条件句」）——`04`·三 第 19 项

**卡住了怎么办（降梯，只降一次）**：
15 秒没动静 → 给一条线索；再 15 秒还没动 → **不算他失败，记「卡在这一步」继续走**，把这一句留到最后回头再看。

---

### S6｜条件定级（判定型）

| | |
|---|---|
| **学生** | 对每条「条件句」点选：**直接 / 间接 / 隐含** |
| **系统** | 只对判为条件句的句子提问；同样三种反应 |
| **步数** | **2—3 条** |
| **依据** | `手册`：「**隐含条件是优等生与普通生的分水岭**」；`04`·三 第 17 项 |

**为什么单独做这一步**：因为「条件句」只解决「这是不是条件」，**不解决「这个条件好不好用」**。
三级判定才是 `04` 里判定的产品靶心。

**这里允许「判不清」**：`02`·T2 已说明——直接 / 间接 / 隐含的边界存在灰度。
所以 S3 备课时如果某条条件**本身就在两级之间**，这一步就只提问、不判级。

---

### S7｜隐含条件追问（开放型）

| | |
|---|---|
| **学生** | 打字回答，**或点「我说不出来」** |
| **系统** | 提问 → 等 → 判 → （未命中）追问一次 → （仍不行）标记并继续 |
| **摩擦** | **全流程最大的一步**（他打字慢） |
| **依据** | `06`·P1·痛点 1；`02`·SWOT S6/S11 |

**提问的样子**：「**这几句里，有没有藏着一个没说出来的东西？**」

**三种走向**：

| 学生 | 系统 |
|---|---|
| **说出一个命中的隐含条件** | 确认——「**就是它。** 这句话题里一个字都没写，但它是这道题的关键」 |
| **说了但没命中** | **追问一次**：「你说的这个，能再说说为什么吗？」——把球踢回去 |
| **追问一次后仍不行** | **不硬逼**——标记「这个卡点没通过」，继续往下走 |

**「说不出来」这个按钮是关键设计**（我们讨论过的那条张力）：

- **它是信号，不是失败**——它直接命中卡点表第二、三行，是我们最想要的信息
- **但它必须可达、却不能被滥用**——如果学生一点就走、每次都用，**产品的开放环节就名存实亡了**
- 做法（**待定，见第八节**）：按钮**延迟出现**，或者**先让他尝试一次**才展开

**对他本人的说法要中性**：不说「你没通过」，说「**这个我们先记下来，待会儿换个题再看看**」——
把「失败」讲成「待确认」。

### S8｜收束

| | |
|---|---|
| **学生** | 听 |
| **系统** | 「**这道题你已经读明白了**」＋ **具体说出他做到了什么** |
| **依据** | `05`·7.1（小然 20:25）；`06`·P1·反直觉洞察 |

**这一步不是评分，是确认。** 说出来的必须是**具体动作**——「今天找隐含条件找得很准」，
而不是「你做得很好」。

**它同时是 Aha Moment 的落点**：`06`·三 记过——学生的 Aha 是「**它没给我答案，但我知道这题在问什么了**」。
这句话的两个分句缺一不可，而 S8 就是让第二个分句成立的那一刻。

**首体验在这里结束。** 这不是流程结束，是**计时结束**：S9 的写解答、S10 的批改、S11 的变式题都属于「可选的后续」，不计入 15 分钟。系统在这里要做的，是把「你可以去写了，写完拍给我看」说成一句邀请，而不是一道必须当场完成的关卡。

### S9｜学生自己写解答 → 拍照

| | |
|---|---|
| **学生** | **在纸上写**，写完拍照交回 |
| **系统** | 不介入。**不给答案、不给提示、不给式子** |
| **依据** | `02`·S2、`05`·9.4、`09`·二（定位 1） |

**这一步是「不给答案」唯一能被看见的地方。**

`05`·4 的价值观里写过：**产品不提供完整解答**。但「不提供」是一个抽象承诺——
**只有让学生自己写出来、并且交上去，这句话才成为一个可观察的事实。**

**为什么是「写在纸上」而不是「屏幕上打字」**：`06`·P1 已确认他打字慢；
而且**在纸上写是他本来的习惯**，产品不该要求他换一个动作。

**从计时口径看，S9 不占产品时间**——这是学生本来就要做的作业，产品在这一步的唯一职责是「不介入」，不是「陪着他写」。

### S10｜批改（原「点评」）

> **本次修改**：原来是「点评」，现在改成「**批改**」——判对错、内部定位错在哪个条件/哪一级、按数量级矫正、并记录。

| | |
|---|---|
| **学生** | 拍照回传解答 → 听 / 看批改结果 |
| **系统** | **批改四步**：① 复述识别结果 → ② 判对错 → ③ **内部**定位错在哪个条件 / 哪一级 → ④ 按数量级矫正并记录 |
| **依据** | `01`·T4（手写识别风险）；`04`·三 第 26 项；本次讨论 |

**批改的四步**：

| 步骤 | 做什么 | 例子 |
|---|---|---|
| **① 复述** | 先把识别到的解答复述一遍，让学生确认 | 「我看到你写的是：设租 x 辆车，列了 45x−10 = 50(x−1)+15，解得 x=5，一共 215 人。对吗？」 |
| **② 判对错** | 判定这份解答是否正确 | 「方程列得对，但答案少了一件事」 |
| **③ 定位（内部）** | 系统内部记下**错在哪一个条件 / 哪一级**；**对学生只说数量级**（决策 8） | 内部：第三句的条件没用上；对学生：「你有三个条件没用上」 |
| **④ 矫正 + 记录** | 按数量级矫正，并把**点名记录写进内部错题库** | 「有三个条件没顾上。这种地方最容易漏，我先记下来」 |

**① 为什么必须在最前**：`01`·T4 已说明手写识别会出错——
**复述是给学生一个成本极低的纠错入口**。他一句「不对，我写的是 50」就能拦住后面所有误判。

**批改可以异步发生**——学生交回后，系统再批改；它不计入首体验的 15 分钟。批改上线前必须过 Gate 2（批改可靠性），见 §8.3。

**「矫正」的边界（这一条必须守住）**：

| ✅ 说 | ❌ 不说 |
|---|---|
| 错了**几个**条件 / 哪一类环节（标注 / 定级 / 隐含） | 具体是哪一个条件、哪一级 |
| 「这个地方最容易漏」 | 「你应该这样算」 |
| （内部记录可以点名） | 对学生点名 |

**为什么这条边界守得住**：产品训练的是**审题**，不是解题。
「你有三个条件没用上」是**审题层面的反馈**——**指出病灶，不给出药方**；
而「正确做法是 50(x−1)+15」是**解法**，它越过了产品的位置（`02`·S2、`05`·9.4）。

**⚠️ 这个改动带来的一个新风险，以及它的解法（已定）**：

批改会告诉学生「你漏了哪个条件」。**S5—S7 的回答已经提交了，改不了**，所以当次不受影响。
但**学生会学到一个模式**：「审题那几步随便答，反正 S10 会告诉我答案。」
——**抄答案的动机可能从「拍照搜题」这条后门重新长出来。**

**解法（已确认）：批改只给「数量级」定位，不点名。**

| ✅ 批改就这么说 | ❌ 不这么说 |
|---|---|
| 「这道题**你有三个条件没用上**」 | 「你漏的是『最后一辆车只坐 15 人』」 |
| 「**有一级判断反了**」 | 「你把间接条件当成了直接的」 |
| 「**少用了一个数**」 | 「15 这个数你没用上」 |

**前者是压力，后者是答案。**
数量级定位把「找」这个动作**留在学生手里**——他仍然要自己回头去把那三个条件找出来。
**而这正是审题训练本身。**

> **这条口径的重要性等同于「不给答案」本身**：一旦批改开始点名，
> 产品就从「陪他读懂」滑回了「替他读懂」——
> **而这是唯一一条不能越过的线。**

> **沿革（2026-10-28）**：S10 的「定位」明确为**内部定位**——对外只说数量级；边界表里原来「错在哪个条件上 ✅」的说法与决策 8 冲突，已按决策 8 收口。

### S11｜变式题（条件触发）

| | |
|---|---|
| **学生** | 走一遍相同流程（但**撤掉部分脚手架**） |
| **系统** | 改条件等级再出一道 → **生成后先自校验** → 才给学生看 |
| **触发条件** | **S5 / S6 / S7 有任一项未通过**，才主动建议 |
| **依据** | `04`·三 第 31—33 项 |

**变式题是什么**：**同情境、同结构，但把条件的等级改深一级**——
直接条件改成间接条件，或把明写的条件藏进隐含。

**它不是「再练一题」，是验收**：原题做完分不清是懂了还是记住了；
**换一道、答案不同了、他还做得出来，才说明他看清的是条件结构。**

**为什么全过的时候不做**：全过的时候证据已经够了，再出一道属于训练泛化——
**那是加练，不是必做**（详见决策 2）。

**两条约束**：生成后**先自校验**再展示（`02`·W11）；**脚手架上撤掉一部分**——
否则它还是「教」，不是「考」。

**首体验不触发**：首体验里 S5/S6/S7 的未通过项照常记下，但变式题留到下一次（或首体验之后的可选环节），不占第一次的 15 分钟。决策 2 的触发条件不变。

> **沿革**：本条在 2026-09-27 一度被改为「必走」，同日改回「**条件触发**」。
> 2026-10-28：补「首体验不触发」——首体验在 S8 收束。

### S12｜生成错题库 + 卡点记录库

> **本次修改**：原来是「生成卡点记录」，现在是**两个库**，且**支持之后重练**。

| | |
|---|---|
| **学生** | 看到「**本次练习结束**」——有明确终点 |
| **系统** | 往两个库各写一笔 |
| **依据** | `04`·三 第 26 项；`03`·5.1；本次讨论 |

**两个库各存什么**：

> **注意**：首体验在 S8 就结束了；S12 的「本次练习结束」是**完整闭环**的终点，不是首体验的终点（见决策 1）。

| 库 | 存什么 | 之后能干什么 |
|---|---|---|
| **错题库** | 做错的原题 ＋ 变式题（含他的解答；「错在哪」内部记录，不向学生点名） | **重做这道题** |
| **卡点记录库** | 四类卡点：标注错 / 定级错 / **隐含条件未说出**（含「推一把过了 / 没推过」）/ 变式题未通过 | **针对某一类卡点再练几道** |

**「重练」是产品第一次有了「回头再练」这个动作**——学生之后可以重做某道错题，或针对某类卡点再练。

**错题库服务谁（2026-10-28 定）**：它首先是**学生的诊断资产**——只对「有未清账目」的学生成立，**不是全体用户的留存解法**。学生侧看到的是「待再看的题」清单；「错在哪」留在内部记录里，不向学生点名（决策 8）。「生命周期第二解法」是待验证假设，不是已成立的决策（见决策 7）。

**我认为这是本轮最重要的改动，因为它对「生命周期只有一年」提供了一个候选解法**——但**只是候选**：

`03`·5.1 那个结构缺陷——「**用户生命周期天然只有一年**」——原本只有一条出路：**扩展到八、九年级**。
错题库 ＋ 重练**不需要改题型**，它把产品的使用从「**卡住时打开一次**」变成「**有没读透的题，就回来**」。
**但这只对有未清账目的学生成立**——通过者没有回来的理由。所以它是**候选解法，不是已成立的第二解法**（见决策 7）。

**它带来两个问题**：

1. **必须有存储**——✅ 已解决（2026-10-01 选 A，后端已建）
2. **「复习 / 重练」这个机制我们原本明确不做了**（见第七节）——现在要做，复杂度要重新评估

### S12 续：卡点记录的四个维度

**记录写什么**（这是**我们讨论定下来的四分法**）：

| 卡点类型 | 触发条件 | 子类 |
|---|---|---|
| 标注错 | 句子类型贴错 | — |
| 定级错 | 条件句三级判错 | — |
| **隐含条件未说出** | 追问一次后仍说不出 | **推一把过了** / **推一把也没过** |
| 变式题未通过 | 只在该触发时记录 | — |

**为什么只有四类、不再加**：`04`·三 已说过——这个记录唯一的价值是**维度长期稳定**。
**维度越多越容易改，越容易改越攒不住。**

**还有一个必须一起记的东西**：**「本次是否一次通过」**（所有人都记）。
它和「变式题通过率」是两个不同的指标——后者只有失败者在做，样本是有偏的（原因见第六节·决策 2）。

### 4.2 各功能「为什么是这样」

**F2 备课——为什么它必须是独立的一步**

它是唯一一个**学生看不见、但决定了所有可见结果**的功能。
`02`·W2 写过：**备课错一次，后面全错，学生会照着错误的标准改自己。**
所以它必须：**在开口前完成**（不能边陪边判）；**产出「不确定」这个状态**（不能假装全都清楚）。

**F4 与 F5 为什么不合并**

学生做的是**两个不同的判断**：这句话**是不是**条件句、这个条件**好不好用**。
合并成一次，等于让他同时做两件事——**出错时也分不清是哪一步错的**，
而这恰好毁掉 F9 的四维记录（它需要知道错在哪一类）。

**F7 为什么不念题**

念题会**剥夺他自己读的动作**——而读正是要练的东西。
语音的角色是**教练**，不是**朗读器**。

**F9 为什么不记分数**

`06`·P1·痛点 3 记过：13 岁**对否定性反馈异常敏感**。
记「分数」会把它变成一个需要赢的东西；记「卡点」才能让它保持成一个**能力训练**。
而且 `02`·S7 已经把「不排名、不贴标签」写进了合规基线。

## 五、功能怎么协作

### 5.1 依赖关系：一条主链，两个旁路

```
        ┌─────────────────────────────────────────────┐
        │  F2 备课  ──产出「解剖结果」──┐              │
        └───────────────────────────────┼──────────────┘
                                        ↓
   F1 拍照 → 确认题目  ──→  F12 会话状态 ──→  F4/F5/F6 逐环推进
                                        ↓           ↕
                                  F3 判定引擎 ←── F7 语音引导
                                        ↓           ↕
                                  F8 降梯机制（超时触发）
                                        ↓
   F9 卡点记录 ←────────────────────────┘
        ↓
   F10 写解答 → 批改（「不给答案」的落点）
        ↓
   F11 变式题（由 F9 决定是否触发；首体验不触发）
```

**三个要点**：

1. **F2 是唯一的「真源」**——F3 判定的每一条依据都来自它。**F2 不产出的东西，F3 不能判**
2. **F12 是调度中枢**——它知道现在在第几步、下一步去哪、什么时候该分支
3. **F9 是唯一的出口**——所有环节的结果最后都汇进它，再由它决定 F11 要不要触发

### 5.2 一次练习的时序（每一步之间传什么）

| S1 拍照 | 照片 | 识别 | 题目文本 → S2 |
| S2 确认 | 题目文本 | 学生校对 | 确定题目 → S3 |

- **S3 的输出喂给了 S5/S6/S7** —— 备课错了，后面三步全错
- **S11 的输入是 F9** —— 变式题不是流程的固定一站，是**由记录触发的分支**

### 5.3 哪些功能之间不能有耦合

| 不该耦合的 | 为什么 |

| **F7 语音 ↮ F3 判定** | 语音只负责**把判定结果说得好听**，不参与判断。混起来会导致「为了话说得顺而改判定」 |
| **F9 记录 ↮ 界面呈现** | 记录是**数据层**，不因为没人看就不认真记（`06`·二 已定：v1 不做家长端） |
| **F11 变式题 ↮ 主流程** | 它是**分支不是必经之路**，不能让它拖长每一次练习 |

## 六、八个关键设计决策

> 这一节记的是**本次讨论真正拍板的东西**，以及每个决定的代价。

### 决策 1｜首体验设 15 分钟，完整闭环不设总时长

**决定**：首体验（**S1–S8**）目标 **≤15 分钟、红线 20 分钟**；完整闭环（S1–S12）**不设总时长，只记录**。单步约束不变——思考下限 15 秒 / 单步上限 40 秒 / 机器响应不设数字。
（40 秒 = 一次降梯周期：15 秒等 ＋ 约 5 秒提示 ＋ 15 秒再等 ＝ 约 35 秒，留 5 秒缓冲。）

**理由**：`06` 的 43 分钟走查拆开是「审题 17 + 写解答 12 + 批改 4 + 变式 9 + 收束 1」。**15 分钟只约束产品陪练的那一段**，不约束学生写作业。`08` 的转折点在 S7（自己说出隐含条件），**转化发生在写解答之前**；`10` 也写了「压不到 15 就砍环节」——这里砍的是「把写作业算进产品时长」，不是审题步骤。

**代价**：

- **首体验看不到「学生自己写」这个最强证据**——但 `08` 的转折点说明转化不靠它，S4 开场也已经划了线。
- **如果实测首体验仍 >20 分钟**，要继续砍 S5 的句数或 S7 的追问，而不是改措辞。
- **完整闭环仍可能到 40 分钟**——它不再被 15 分钟约束，只被单步约束和「可选中途停」保护。

> **沿革（2026-10-28）**：原题为「取消总时长目标，改设单步约束」，把 43 与 15 的冲突整个绕开了。现改为两段口径：**首体验 ≤15（S1–S8），完整闭环只记录**。

---

### 决策 2｜变式题是补考，不是必考

**决定**：只在 **S5 / S6 / S7 有任一项未通过**时主动建议；全部通过时不做。

**理由**：全过的时候证据已经够了，再出一道属于训练泛化——**那是加练，不是必做**。
没通过的时候，「是这道题的问题还是真没掌握」必须回答，否则记录里会留一条脏数据。

**代价**：**「变式题通过率」的样本变得有偏**——只有失败者在做。
所以记录里必须把**「本次是否一次通过」**（所有人）和**「变式题是否通过」**（失败者）分开记。

**一个因 F14（错题库）才浮现的边界**：
**只有失败者的题会进错题库。** 这不是缺陷，是定位——错题库是**学生的诊断资产**，只对「有未清账目」的学生成立；**它不是全体用户的留存解法**。所以「生命周期第二解法」只能作为待验证假设，不能写成决策（见决策 7）。

**变式题仍按本条条件触发，但首体验不触发**——首体验在 S8 收束，S11 留到下一次或可选后续（见决策 1）。

> **沿革**：本条在 2026-09-27 一度被改为「必走」，**同日改回「补考不是必考」**。
> 2026-10-28：补「首体验不触发」，并把「错题库副作用」改为「边界」。

**代价（必须一起记）**：

| 代价 | 说明 |
|---|---|
| **变式题通过率样本有偏** | 只有失败者在做——所以要分开记两个指标（见上） |
| **错题库只会收到失败者的题** | 见上一条边界；这是定位，不是缺陷 |
| 一个反向的好处 | 多数练习**保持短流程**，不因为少数人的失败拖累所有人 |

---

### 决策 3｜「说不出来」是信号，不是失败

**决定**：S7 提供显式入口；追问不超过一次；追问后仍说不出就**标记「卡点未通过」继续走**；
对他本人说「**这个我们先记下来，待会儿换个题再看看**」。

**理由**：说不出来直接命中卡点表第二、三行——**那正是我们最想要的诊断信息**。

**代价（这条最重要）**：**如果入口太容易点，它就会变成默认按钮**，产品退化成全点选流程——
而 `04` 里写过：**「好用但无用」**。所以它必须**可达但不能无摩擦**，具体做法见第九节。

---

### 决策 4｜卡点只记四类，不再增加

**决定**：标注错 / 定级错 / 隐含条件未说出（含「推一把过了」「推一把也没过」）/ 变式题未通过。

**理由**：记录唯一的价值是**维度长期稳定**——`03`·5.1 已说明用户只留一年，
**积累本来就短，再改维度就真的白攒了。**

**代价**：**有些真实的问题会被挤在外面**。比如「他知道答案但说不清」和「他根本不知道」——
目前都归进「隐含条件未说出」这一格，分不开。

---

### 决策 5｜备课是唯一真源，且必须能输出「不确定」

**决定**：F2 在开口前独立完成；**F2 没产出的东西，F3 不能判**；F2 不确定的项**标记为不判定**，
走到那里改为提问。

**理由**：`02`·W2——备课错一次，后面全错；`05`·8.3——**误判正例率必须为 0**。

**代价**：**备课要花时间**（学生要等），而且**产出「不确定」会让产品看起来不够聪明**。
这是刻意的取舍：**宁可显得笨，也不能教错。**

---

### 决策 6｜v1 不做家长端、不做教师端界面

**决定**：家长端与教师端在 v1 **完全不存在**；卡点记录照做，但只作为数据层。

**理由**：`06`·二——家长一周只有 1 个触点、约 30 秒；建立这个触点需要专门的推送与展示层，属于付费通路，不在 v1 的验证范围。教师产品内行为 0 次。

**代价**：**v1 没有任何对外输出 → 没有付费通路 → v1 不是商业版本，是验证版本。**
这一点必须提前说清楚，否则后面会有人问「为什么做了个收不到钱的东西」。

> **沿革（2026-10-28）**：原理由写「没有后端就没有触点」；选 A 之后后端已建，这个理由不再成立。现改为「家长端需要专门的推送与展示层，不在 v1 的验证范围」——**决定不变，理由更新**。

---

### 决策 7｜建立错题库 ＋ 重练（定位：学生的诊断资产）

**决定**：S12 生成**两个库**（错题库 ＋ 卡点记录库），并支持之后**重练**——重做某道错题，或针对某类卡点再练几道。**错题库服务的是「有未清账目的学生」**，不是全体用户；「生命周期只有一年的第二个解法」是**待验证假设**，不是已成立的决策。

**为什么仍然重要**：对没读透的学生，它把产品的使用从「**卡住时打开一次**」变成「**有没读透的题，就回来**」——**这是产品第一次有了「回来的理由」，但只对这部分学生成立。**

**可见性口径**：错因记录**内部可见**；学生侧只看到「**待再看的题**」和数量级，不点名（决策 8）。**不要叫学生「错题库」**——学生侧叫「待再看的题」。

**代价（三条，都不是小事）**：

| 代价 | 说明 |
|---|---|
| **必须有存储** | ✅ 已解决（2026-10-01 选 A，后端已建） |
| **覆盖率有限** | 只覆盖有未清账目的学生；通过者没有回来的理由——**这是定位，不是 bug** |
| **生命周期作用未验证** | 「第二解法」是假设，要在 P1/P2 用回访数据验证，不能现在写成结论 |

**产品形态确实变了**：从「一次性工具」变成「**带循环的训练系统**」。这会影响定位表达（`09`）与商业模型（`03`）——但影响多大，取决于上面那条假设是否成立。

> **沿革（2026-10-28）**：原稿把「第二条出路」写成已成立的解法，与决策 2 的「做得好的学生没有回来的理由」直接矛盾。现降为假设，并明确服务对象与可见性。

### 决策 8｜批改只给「数量级」定位，不点名

**决定**：S10 批改指出**错在哪个环节、错了几个**，但**不指出具体是哪一个条件、哪一级**。

| ✅ 就这么说 | ❌ 不这么说 |
|---|---|
| 「你有**三个**条件没用上」 | 「你漏的是『最后一辆车只坐 15 人』」 |
| 「有**一级**判断反了」 | 「你把间接条件当成了直接的」 |
| 「少用了**一个**数」 | 「15 这个数你没用上」 |

**理由**：**让「找」这个动作留在学生手里。**
他听完全要自己回头去把那三个条件找出来——**而这正是审题训练本身。**

**更深一层的理由**：一旦批改开始点名，学生就会学到「**审题那几步随便答，反正 S10 会告诉我**」——
**抄答案的动机从「拍照搜题」这条后门重新长回来。**
`02`·S2 花了很大力气把产品的合规身份建立在「不给答案」上，
**而批改点名，等于用另一种方式把答案给了出去。**

**代价（必须一起记）**：

| 代价 | 说明 |
|---|---|
| **批改的即时感变弱** | 学生听不到「你错在哪」，会有一点不解渴——**这是刻意的** |
| **他可能找不出来** | 那时靠 S11 变式题去验证，而不是靠 S10 说出来 |
| **这条口径要写死在提示词里** | 因为「AI 乐于助人」的默认行为**正好和它相反**——模型天然想说得更具体 |

> **这条口径的重要性等同于「不给答案」本身。**
> 一旦越过，产品就从「陪他读懂」滑回「替他读懂」。

**这条口径也约束 F14 的可见性**：错题库内部可以记「错在哪」，但学生侧只显示「待再看的题」和数量级，不展示点名记录（见决策 7）。

### 8.3 实测阶梯：红线在最前面

**Gate 0｜判定可靠性（P0，任何家庭实测之前）**

拿 50—100 道真实七年级应用题，测模型对**句子类型**和**条件句三级**的判定准确率，**重点统计「把正确判成错误」的比例**（`02`·SWOT P0）。判定用例里必须包含「**集合外但成立**」的学生说法——那才是红线的真正考验。

通过标准：句子类型准确率 ≥90%；条件句三级准确率 ≥90%；**误判正例率 = 0**（红线）；说不准率不过高（太高说明系统不敢判，同样是失败）。

**这一条不通过，F3 的判定就不能上线**——那时产品形态要改（三级判定降级为引导性提问），**而不是硬着头皮写代码。**

**Gate 1｜首体验（P1，3—5 个家庭）**

首体验（S1–S8）**≤15 分钟、完成率 ≥70%**；同时记录完整闭环时长。如果首体验压不到 15，按 `10` 的规矩**砍环节，不优化措辞**。

**Gate 2｜批改可靠性（F10 上线前）**

判「这句话是不是条件句」是有界问题；**判「这份解答对不对」要先把题解出来**——错误面大得多，而红线仍是「误判正例率 = 0」。**测试集还没建，必须在 S10 上线前建。**

**Gate 3｜其余**

重练的前端入口、开放型判定的实现等（见第九节）。

**两个必须说清的事实**：

1. **P0 工具已经能跑，但只覆盖「判定」，没覆盖「批改」**——`流程步骤/3.验证与商业/p0_判定可靠性测试/` 现在测的是句子类型、条件句三级、判定用例；批改的标注集要另建。
