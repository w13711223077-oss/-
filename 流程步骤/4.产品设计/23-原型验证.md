# 23. 原型验证 — 数学审题逐题陪练

> 上游：20、22。下游：24。
> 样板 41 号文是「方案 → Review → 原型生成 → 需求标注」四步流 + 14 个 HTML 原型；我们只有 1 个原型，但四步不省。

## 一、四步流

### 第 1 步：方案设计（七维度）

每个屏/流程必须写清七件事：

| 维度 | 问题 | 本项目的例子 |
|---|---|---|
| 页面目标 | 这一屏只干哪一件事 | S5 只让学生判断「这一句在题里干什么」 |
| 用户角色 | 谁在用、什么状态 | 七年级学生，作业卡住、打字慢 |
| 信息架构 | 这一屏有哪些信息、从哪来 | 句子原话 + 4 个选项 + 反馈 |
| 业务流程 | 正常 + 分支 + 替代 | 一致/不一致/不判定；15s/40s；说不出来 |
| 状态规则 | 加载/空/错/超时 | 读题加载、备课失败、40 秒记卡住 |
| 异常处理 | 出错怎么办 | 重拍、粘贴、重试、丢弃 |
| 验收标准 | 怎么算通过 | 首体验 ≤15 分钟、完成率 ≥70% |

### 第 2 步：方案 Review（三关）

1. **业务完整吗**：S1—S8 有没有断头路？每个出口都有下一屏或终止？
2. **状态/异常覆盖吗**：加载、空、错、超时、退出、说不出来都定义了？
3. **能直接交给开发吗**：字段、接口、状态码、文案都能对上 19/20？

缺一关退回第 1 步。

### 第 3 步：HTML 原型

- 位置：`流程步骤/5.创建项目骨架/v1/index.html`
- 形态：单页 HTML + 原生 JS；零构建；`python run.py --static` 同源发。
- 沙盘不是成品：允许桩模式、允许写死话术，但**状态与接口必须是真契约**。

### 第 4 步：需求标注

每个可交互元素回答三件事：

| 标注 | 回答 |
|---|---|
| 对应哪条需求 | 11·§3.2·S5 / 15·§7 |
| 体现在哪个元素 | `.opt[data-v=背景]` |
| 怎么验证 | 点击后 POST /answer，返回 verdict；测试 test_flow |

## 二、原型检查清单

### 2.1 形态

- [ ] 没有首页、没有菜单、没有登录
- [ ] 打开就是 S1 拍照/粘贴
- [ ] 没有「答案」「解析」入口
- [ ] 没有分数、排名、积分、打卡、再来一题
- [ ] 没有姓名/学校/班级/手机号字段

### 2.2 流程

- [ ] S1→S2→S3→S4→S5→S6→S7→S8 全部可走通
- [ ] 识别错可重拍/粘贴
- [ ] 备课失败可重试
- [ ] 15 秒提示、40 秒记卡住
- [ ] S7「说不出来」延迟出现
- [ ] S8 有明确终点与具体动作
- [ ] 中途退出是丢弃，不写脏记录

### 2.3 判定与可见性

- [ ] Gate 0 前所有判定返回「不判定」
- [ ] 不出现「你错了」「你又漏了」
- [ ] 学生端看不到具体句子/条件的错因
- [ ] 不返回 `answer/solution/final_value`
- [ ] 桩模式明确标注

### 2.4 技术与体验

- [ ] 单页、零构建、无第三方依赖
- [ ] 移动端可用；按钮 ≥44px
- [ ] 语音可开关；不读题目正文
- [ ] 加载/错误/空状态都有文案
- [ ] JS 语法检查通过；后端测试全绿

## 三、验证谁、验证什么

| 对象 | 验证什么 | 不验证什么 |
|---|---|---|
| 1—2 个学生 | 能不能独立走完；退在第几步 | 不提分、不承诺效果 |
| 1 位教师 | 判得准不准；第一句话是否澄清「不是搜题」 | 不要求推荐/背书 |
| 3—5 个家庭（Gate 1） | 首体验时长、完成率、家长能否复述「不给答案」 | 不做班级/学校级统计 |
