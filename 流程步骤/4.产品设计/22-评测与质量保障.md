# 22. 评测与质量保障 — 数学审题逐题陪练

> 上游：15、16、21。下游：23。
> 样板 31 号文用 L0—L6 七层评测 + 快慢双层 + 判官校准；我们按同样思想，但把门禁压缩成 **Gate 0—3**，并把「红线」放在最前面。
> 一句话：**先证明判得准，再证明学生走得完，再证明批改可靠，最后才谈其余。**

---

## 一、四道门

```text
Gate 0 判定可靠性（P0，任何家庭实测之前）
   ↓ 误判正例率 = 0；句子类型/三级 ≥90%；说不准率不过高
Gate 1 首体验（3—5 个家庭）
   ↓ 首体验（S1—S8）≤15 分钟、完成率 ≥70%
Gate 2 批改可靠性（S10 上线前）
   ↓ 误判正例率 = 0；测试集已建
Gate 3 其余（重练入口、开放型判定、变式、家长端…）
```

**顺序不可调换**：Gate 0 不过，产品形态要改（三级降级为引导性提问），不是硬写代码。

---

## 二、Gate 0：判定可靠性

| 项 | 内容 |
|---|---|
| 样本 | 50—100 道真实七年级应用题，人独立标注 |
| 测什么 | 句子类型（4 类）、条件句三级、集合外但成立的说法 |
| 指标 | ① 句子类型准确率 ≥90%；② 三级准确率 ≥90%；③ **误判正例率 = 0**；④ 说不准率不过高 |
| 工具 | `流程步骤/3.验证与商业/p0_判定可靠性测试/`（已跑通，含故意做错的自检样本） |
| 不通过 | 三级降级为引导性提问；产品仍成立，但少一层自动诊断 |
| 产出 | `P0_报告.txt` + `P0_摘要.json`（可挂门禁） |

> 红线是「把学生做对的判成错的」= 0；不是“越低越好”，是开关。

---

## 三、Gate 1：首体验

| 指标 | 目标 | 红线 |
|---|---|---|
| 首体验时长（S1—S8） | ≤15 分钟 | >20 分钟失败 |
| 首体验完成率 | ≥70% | 无人在前 3 分钟退出 |
| 家长能说出「它不给答案」 | ≥80% | — |
| 中途退出位置 | 记录退在第几步、屏幕停在哪 | — |

**测法**：3—5 个真实家庭，学生独立走；家长在旁边看但不介入；记录每一步耗时与退出点。
**产出**：首体验实测记录 + 摩擦点清单 + 一个能回答「15 分钟能不能做到」的数字。

---

## 四、Gate 2：批改可靠性

| 项 | 内容 |
|---|---|
| 为什么难 | 判「这句是不是条件句」是有界问题；判「这份解答对不对」要先把题解出来 |
| 测试集 | 50—100 份真实学生解答（手写拍照）+ 人标注；**尚未建** |
| 指标 | 误判正例率 = 0；定位可用率；学生自纠率 |
| 不通过 | S10 不上线；只保留审题弧线 |
| 与 Gate 0 的关系 | 独立门禁；不能因为 Gate 0 过了就默认批改可靠 |

## 五、L0—L6 映射

| 层 | 样板 | 我们 | 何时跑 |
|---|---|---|---|
| L0 | 工具自身正确性 | 单元测试：schema/flow/store/prep/judge | 每次提交 |
| L1 | 行为轨迹 | 流程测试：S1→S8 状态转移、守卫、降梯、说不出来 | 每次提交 |
| L2 | 输出质量 | P0 判定报告；S8 话术抽检 | Gate 0 / 发布前 |
| L3 | 安全护栏 | 答案泄露扫描、可见性投影测试、无身份字段 | 每次提交 + 发布前 |
| L4 | 性能预算 | 读图/备课/判定延迟；首体验时长 | 每次提交（软警告） |
| L5 | 稳定性回归 | 48+ 测试、桩模式端到端 | 每次提交 |
| L6 | 端到端任务 | Gate 1 家庭实测 | 发布前 |

**快慢双层**：L0/L1/L3/L4/L5 秒级、零模型成本、每次提交；L2/L6 花钱花时间、发布前。**L3 的答案泄露是红线，任何失败一票否决。**

## 七、评测先行

1. 先写“什么算好”的断言（此时红）。
2. 写实现让它变绿。
3. 红线用例（误判正例、答案泄露、越权）永远放在最前，失败即阻断。

**不伪造通过**：
- 桩模式只证明管道通，不证明判定准。
- 0/0 不是 100%；没测的维度标 `null`，不标满分。
- 判定未上线时，记录 `undetermined`，不写成 `pass`。
