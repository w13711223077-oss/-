## 五、三个判定 J1—J3

### J1 数据模型是否支撑 Gate 0—3 的实测与后续 S9—S12 扩展

**判定：有条件通过。**

前置条件：

1. Gate 0 与数据模型无关（P0 用独立标注文件），可直接跑。
2. Gate 1 之前必须补：`schema_version` + 读时迁移（DM-02）、`expires_at`/删除入口（DM-03）、EventLog 最小写入（DM-08）；否则实测数据不可复现、不可清理。
3. S9—S12 之前必须另立数据模型变更：18 有 `ExerciseRecord`/`Variant`/`WrongItem`，但**没有 SolutionAsset（学生解答图片/文本）与 GradeResult（批改结果/数量级定位）实体**；直接扩展会返工。
4. Answer/Checkpoint 的单一真源必须先定（DM-01），否则 S10/S12 会读错源。

### J2 认证体系能否在「不推翻 ADR-001/003」的前提下补齐

**判定：有条件通过。**

前置条件：

1. 用标准库实现：`secrets.token_urlsafe` / `hmac.compare_digest` / `hashlib` / `http.cookies`；token 索引可落 JSON/JSONL，不引数据库（符合 ADR-001/003）。
2. 必须新增 `Session.owner_ref` / `expires_at` / `revoked_at` 三个字段（18 现无）；属于**向后兼容的新增字段**，旧会话缺省为「无 owner / 不过期 / 未吊销」，不算破坏性变更，但必须配迁移（DM-02）。
3. Origin 白名单 + 最小限速是上线门禁；可以先用内存实现，不引第三方包。
4. 不引入账号/登录（v1）；v2 若加监护人账号，仍可用标准库 + JSON，但会推翻「v1 无账号」而不是 ADR-001/003。

### J3 本期（方向 A：Gate 0 实测工程）在不修上述问题的情况下能否开工

**判定：通过（仅限 P0 实测工程本身）。**

- Gate 0 是离线验证工具：样本/标注/脚本/报告都在 `p0_判定可靠性测试/`，不经过 session API、不依赖 auth、不写产品库；K1—K5 不影响它。
- **但**：Gate 0 通过后不得直接把 `P0_已通过=True` 暴露给真实家庭——`_判()` 未实现（`judge.py:60-63`），且 AU-01/02/03 未修。翻开关与家庭实测必须先过 J2 的前置条件。
- 允许现在开工的范围：题集、标注、runner、报告、门禁检查；不允许：改 S1—S8、加认证、翻开关。
