# P0 判定可靠性测试

> **这是整个项目的第一个技术动作。** 在做任何产品代码之前，先回答一个问题：
> **模型判「学生标得对不对」，判得准吗？**

---

## 为什么先做这个

`02-SWOT分析` 把这条定为 **P0**。理由：

产品的一切都建立在「系统能判断学生做得对不对」之上——
四维卡点记录、变式题触发、批改，全都依赖它。

**而误判一个正确的答案，学生会照着一个错误的标准改自己。**
所以 `05-产品愿景` 里把「误判正例率」设为**红线：必须为 0**。

**这一条不通过，产品形态就要改**（条件句三级降级为引导性提问），
**而不是硬着头皮写代码。**

---

## 怎么用（三步）

### 第一步：填题目

打开 `sample_annotation.json`，照里面的结构往下加题。

每题要填三样：

| 字段 | 是什么 |
|---|---|
| `sentences` | 把题目拆成句子，每句标**类型**（背景/条件/问题/指令）；条件句还要标**级别**（直接/间接/隐含） |
| `implicit` | 这道题藏着的隐含条件——**写成集合，不是单点**（可能有多个说法） |
| `adjudication_cases` | **模拟学生的说法**，每条标上「对 / 错」。**这一栏是测红线的关键** |

`adjudication_cases` 里**一定要放这种**：

```json
{"student_says": "坐的车数和总人数是不变的", "truth": "correct",
 "why": "集合外但成立——学生换了说法，说得对，不能判错"}
```

**这类「说得对但不在标准措辞里」的用例，才是红线的真正考验。**
样本里已经放了 4 条，标了 ⚠️。

### 第二步：跑判定

```bash
# 先验证管道（不调 API，30 秒）
python p0_judge.py --baseline

# 再真跑（要 API key）
set DEEPSEEK_API_KEY=sk-xxxx        # Windows
export DEEPSEEK_API_KEY=sk-xxxx     # macOS / Linux
python p0_judge.py
```

### 第三步：看报告

```bash
python p0_compare.py
```

报告出四个数字，**前两个是能力，后两个是风险**：

| # | 数字 | 看什么 |
|---|---|---|
| ① | 句子类型准确率 | 低于 90% → F4 逐句标注不能自动判对错，只能给提示 |
| ② | 条件句级别准确率 | 低于 90% → F5 条件定级要降级，**这是产品靶心，降级代价最大** |
| ③ | **误判正例率** | **> 0 就是红线已破，不能上线** |
| ④ | 说不准率 | 太高说明系统不敢判——产品会变得没有反馈，**同样是失败** |

报告会直接告诉你是**哪一条用例**破了红线，以及模型给的理由。

## 样本数据里有 3 道题

| 题 | 用来测什么 |
|---|---|
| P001 研学租车 | 手册原题。含「两问」和两条隐含条件 |
| P002 行程问题 | 含「前一半路程 ≠ 前一半时间」这个典型误读 |
| P003 工程问题 | 含「休息的 5 天里只有乙在干」这种藏在状态里的隐含条件 |

**15 个判定用例里，有 4 个是「集合外但成立」**——专门用来考红线。

> ⚠️ **这 3 道题只是格式示范，不是你真正要用的题。**
> P0 要求 **50—100 道真实七年级应用题**，而且
> **样本太小算出来的百分比没有统计意义**——3 道题错 1 条就是 33%。

## 文件名

| 文件 | 是什么 |
|---|---|
| `sample_annotation.json` | **标注（标准答案）**。人手工标，作为对照基准 |
| `p0_judge.py` | 拿标注去问模型；输出 `out/model_output.json` |
| `p0_compare.py` | 对照，出报告 |
| `out/P0_报告.txt` | 给人看的报告 |
| `out/P0_摘要.json` | 给机器看的数字（可挂门禁） |
| `out/_broken_output.json` | **故意做错的输出**，用来验证工具能报错 |

### `_broken_output.json` 是什么

它是我人为改错的一份模型输出（把一条对的判成错的、一条错的判成对的、一句条件句判错级别）。
**用途：验证这个工具能发现问题，而不只是能通过。**

```bash
python p0_compare.py --model out/_broken_output.json
# 应该看到：误判正例率 11.1%、红线已破、退出码 1
```

**一个永远不会失败的检查，等于没有检查。** 每次改动 `p0_compare.py` 之后，拿这份跑一遍。

---

## 出问题先看哪里

**准确率明显低于 90% 时，先别改产品——先看是不是提示词没写清楚。**

提示词在 `p0_judge.py` 顶部的 `SYSTEM_PROMPT`。那里定的就是产品里
**F2 备课 / F3 判定** 的口径。改那里 = 改产品行为。

**改完提示词重跑一遍**，如果数字上来了，说明问题在提示词；如果上不来，才是模型能力问题——
那时候才轮到改产品形态。
